# hand-remade: 사람 기조를 지킨 채 남은 약점을 메운 버전

[hand-completed/](../hand-completed/)(버그와 TODO를 마무리한 버전)에서 출발해, Codex와 비교했을 때 드러난 약점 중 **사람 방식으로도 쉽게 메울 수 있는 것**만 고쳤습니다. 폴더마다 `changes_from_completed.diff`가 완결판과의 차이입니다.

## 지킨 것

- 프로그램 하나 = `.c` 파일 하나. 공통 라이브러리, 헤더, 숨긴 타입은 만들지 않음
- 2칸 들여쓰기, K&R 중괄호, `perror(path); return 1;`, 짧은 영어 주석
- 저자의 CLI 모양 유지(`find PATTERN PATH`, `rm [-r] path...`)
- 직접 구현하지 않고 POSIX가 이미 주는 것을 씀(`scandir`, `fnmatch`, `strdup`, `utime`)

## 바꾼 것

| 과제 | 약점 | 수정 | 줄 수 |
|---|---|---|---|
| 02 tree | 정렬 출력 없음 | **`-s` 옵션**으로만 정렬(`scandir` + `alphasort`). 기본은 지금처럼 스트리밍. 항목 처리를 `visit()`으로 빼서 두 경로가 함께 씀 | 50 → 72 |
| 05 rm | 폴더를 확인 없이 재귀 삭제 | **`-r` 없이는 폴더를 거부**(`tree: is dir, use -r`) | 56 → 66 |
| 05 find | 부분 문자열만 지원 | **`fnmatch` 글롭**(`'*.c'`, `'main.?'`). 경로를 직접 주면 그 경로의 마지막 이름으로 비교 | 61 → 66 |
| 05 mkdir | `-p` 없음 | **`-p`**: 경로를 `/`에서 끊어 앞에서부터 만들고, 이미 있는 폴더는 성공으로 처리(같은 이름의 파일이면 실패) | 16 → 41 |
| 07 연결 리스트 | `append`가 매번 끝까지 순회(O(n)). `apply` 결과가 `int`라 넘침 | **`append`가 새 꼬리를 반환**하고 호출자가 그것을 들고 다님(새 구조체 없음). `apply`/`add`/`sub`를 `long`으로 | 53 → 53 |
| 09 해시 테이블 | `SIZE 5` 고정, 글자 합 해시(애너그램 충돌), 키를 복사하지 않음 | **`SIZE 65536` + djb2**(저자가 영상에서 직접 비교한 해시). 키는 `strdup`으로 복사해 테이블이 소유. 큰 배열이라 `static`으로 둠 | 70 → 77 |
| 전체 | 회귀 테스트 없음 | **[tests.sh](tests.sh)**: 빌드하고, 실행하고, 기대 출력과 비교(17개 시나리오) | +44 (테스트) |

03(움직이는 숫자)과 08(동적 배열)은 메울 약점이 없어서 완결판 그대로입니다.

**메우지 않은 것**(사람 기조와 충돌하거나 쉬운 수정이 아님)
- GNU 옵션 전부와의 호환: `touch -t` 날짜 파싱, `cat -v`, `mv -i/-n`과 다른 장치 간 복사, `find` 표현식 언어
- 모르는 사용자를 위한 방어적 API: 숨긴 타입, NULL 허용 계약
- 해시 테이블 자동 확장: 지금은 "약 100만 키까지"라는 가정을 주석에 적어 둠. 확장하려면 버킷을 동적으로 할당하고 재배치하는 약 20줄이 필요
