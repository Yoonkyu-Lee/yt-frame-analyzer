# 출처 (sources)

영상을 프레임만으로 해체 분석한 원자료입니다. 채널(발행 주체)마다 폴더 하나를 둡니다. 한 채널의 주장은 그 폴더 안에만 적고, 여러 출처를 근거로 하는 원칙만 [northstar](../northstar/)로 올립니다.

|---|---|---|---|---|

## 출처끼리의 관계

### Hayyoth와 poteto: 같은 적, 다른 목적지

둘 다 슬롭의 원인을 "AI가 멍청해서"가 아니라 **코드가 사람과 기계 모두에게 주는 입력의 질**로 봅니다. 차이는 누가 마지막에 이해하느냐입니다.

| | Hayyoth | poteto (Lauren Tan) |
|---|---|---|
| 목적 | 사람이 모든 줄을 이해한다 (배움) | 사람이 코드를 읽지 않아도 믿을 수 있다 (처리량) |
| 품질을 지키는 장치 | 작게 짓기, 경고 최대(C3), 진짜 도구와 출력 대조(A1), 손으로 다시 쓰기 | 린트, 금지된 API, 폴더 경계, 런타임·형식 검증, 퍼징 |
| AI의 자리 | 이해를 대신하지 못함. 답을 버리거나 손으로 다시 짠다(E1) | 코드를 쓰고 스스로 검증하는 주체. 사람은 증거를 본다 |
| 주석 | 작업 중에는 계획과 설명으로 쓰고, 마지막에는 지운다(B2, F1) | 99% 금지. 에이전트가 변명을 적는 탈출구이고 강제할 수 없다 |
| 복사 | 자기 옛 코드를 복사해 시작한다(B4). 자기 코드가 깨끗하니 문제가 없다 | "복사가 다음 복사를 부른다." 그러니 코드베이스를 깨끗하게 둬야 한다 |
| 숫자 | 영상 하나, 몇십 줄 | 한 달 PR 10,926개, 기여자 227명 |

**겹치는 원칙**(northstar 후보, 두 출처가 독립적으로 말함):
1. 코드는 다음 작성자(사람이든 에이전트든)의 교과서다. 땜질은 패턴으로 복사된다.
2. 미묘한 판단이 필요한 도구는 쓰지 않는다. Hayyoth는 최소한의 언어 기능(D2), poteto는 `useEffect` 금지.
3. 기계가 잡을 수 있는 것은 기계에 맡긴다. 경고 최대(C3), 린트 규칙.
4. 결과는 실제로 돌려서 확인한다. Hayyoth는 진짜 `cal`과 나란히 비교, poteto는 앱을 조종하는 CLI와 증거.

poteto 발표에서 들여온 것(교훈은 기계 검사로, 기준 방법과의 대결, 의심 원장, 증거 리뷰, 상시 회의 루프)은 northstar에 **가설**로 반영했습니다: [NORTHSTAR](../northstar/NORTHSTAR.md) C11·C12·L13~L16, [WORKFLOW](../northstar/WORKFLOW.md) 8단계, [LESSONS](../northstar/LESSONS.md) 마지막 절.

**부딪치는 지점**: "사람이 코드를 읽어야 하는가". poteto도 "yes, you should read the code sometimes" 슬라이드를 넣었습니다. 그러니 두 출처의 차이는 읽기를 없애는 것이 아니라 **매일의 리뷰를 증거로 바꾸고, 읽기는 구조를 가꾸는 데 쓰는 것**으로 정리할 수 있습니다.

### 출처 밖 참고: ponytail (Claude Code 스킬, 2026-11-17 확인)

[DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)은 "게으른 시니어 개발자" 프롬프트 하나(약 50줄)입니다. 코드를 쓰기 전에 사다리를 위에서부터 내려가 처음 맞는 칸에서 멈춥니다.
1. 이게 필요한가
2. 코드베이스에 이미 있나
3. 표준 라이브러리나 플랫폼 기능으로 되나
4. 설치된 의존성으로 되나
5. 한 줄로 되나
6. 그래도 아니면 최소한의 코드

그 밖의 규칙:
- 신뢰 경계 검증, 데이터 손실 방지, 보안, 접근성은 절대 줄이지 않습니다.
- 알려진 한계는 `shortcut:` 주석으로 남기고, 그 주석들을 부채 원장(`/ponytail-debt`)으로 모읍니다.

| 관계 | 내용 |
|---|---|
| 같은 방향 | 사다리는 northstar의 C4(플랫폼이 먼저), L3·L4(추상화·의존성 최소), C9·L12(방어는 경계에서)와 거의 같습니다. Hayyoth의 D1(추상화는 필요해질 때까지 만들지 않는다)과도 같습니다. 자체 벤치마크는 정직하게 적었습니다: 숨겨진 검사 통과율은 스킬 없는 쪽과 같고(96.7% 대 95.6%), 줄어든 것은 크기와 비용입니다 |
| poteto와 충돌 | `shortcut:` 주석은 poteto가 말한 "옳은 일을 안 한 변명을 적는 주석"과 같은 모양입니다. 원장으로 모은다는 점은 다르지만, 강제되지 않는 글입니다 |
| 피라미드에서의 자리 | 프롬프트 한 장이므로 피라미드의 **글(prose) 칸**입니다. 생성 순간에 덜 쓰게 하는 장치이고, 이미 쌓인 슬롭을 의도 기준으로 다시 붓거나(리캐스트) 교정을 린트로 내리는 장치는 아닙니다 |
| 아이러니 | 프롬프트는 50줄이지만 저장소는 에이전트 20종 어댑터, 상태 표시줄, 비용 대시보드 등 코드 약 11,800줄(테스트·벤치마크 포함)입니다. pstack도 스킬 58개, 코드 약 13,700줄(테스트 포함)입니다 |
