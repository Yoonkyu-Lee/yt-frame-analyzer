## Observations

- Speaker (Lauren Tan) wraps up the formal verification section: TLA+ and Lean are "certainly not a silver bullet", treated as "another tool, another layer in our agent's environment". This is a bare assertion; the slide only lists what each tool does (TLA+ models state machines, Lean proofs check implementation for bugs) and points to a skills repo.
- She then shows UI property-based testing with the Bombadil library, over a fast screen recording of fuzzing the Grok Bot chat UI (garbled random messages, opening dialogs and the command palette). The only quantified claim is "caught a few UI bugs for us already" ("a few", no number, no specific bug shown). The recording shows the fuzzing, not any bug found. She says "we just started looking at" it, so it is early.
- Then she zooms out to evidence about trust and verification, using two tweets by Cindy Sridharan (public author, display name written). Tweet 1 (May 15, 2026): AI-generated PRs with subtle bugs merged and took days to fix; "velocity isn't going up". Tweet 2 (Nov 5, 2026): she no longer hits these problems; what was missing was a verification process; "70% of my daily token spend goes into verifying patches, and only ~20-30% into creating them." These are screenshots of a third party's self-reported experience, so they are anecdotal, which the May tweet itself says ("Might be anecdotal"). The speaker adds a bare assertion that this "tracks with what I see as well, that most of my token usage goes to verification", with no figure for her own usage in this segment.
- Speaker's framing: verification is what makes agents trustworthy, and in a mature setup most of the token budget goes to verification rather than generation.
