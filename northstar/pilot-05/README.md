# pilot-05: 의미 압축 루프 실험

**질문**: 바이브 코딩 결과물을 "위에서 아래로, 이것이 무엇을 위해 있는지 먼저 적고, 적지 못하는 것은 지우거나 다시 쓰는" 라운드를 반복해 줄이면 실제로 줄어드는가? 줄인 결과는 의도를 지키는가? 그냥 AI에게 "최소화하라"고 시키는 것과 무엇이 다른가?

**대상**: [vibe-coding/05](../../experiments/vibe-coding/05_linux-file-utils/)에서 Codex가 쓴 리눅스 파일 유틸(`touch cat mkdir mv rm find`) 812줄.

**한 줄 결과**: 812줄이 291줄(−64%)이 되었고 `cat`은 약 3.5배 빨라졌습니다. 다만 의도 테스트 60개만 믿고 압축한 r3에서는 회의론자 리뷰가 퇴행 5종(실패 테스트 9개, ASan으로만 잡힌 메모리 오류 1개)을 찾아냈습니다. **압축은 오라클의 구멍만큼 의도를 잃습니다.**

## 대조군: "최소화하라"만 준 Codex

같은 r0를 Codex(gpt-6.1-sol, reasoning high, 샌드박스 쓰기 허용)에게 주고 "동작을 유지하면서 코드베이스를 최대한 최소화하라"고만 시켰습니다([PROMPT.md](control/PROMPT.md)). `INTENT.md`와 테스트는 주지 않았습니다. 결과는 [control/](control/)에 있습니다.

| | r0 | 대조군 | 압축 루프(r4) |
|---|---|---|---|
| 코드 줄 | 812 | 752 (−7.4%) | **291 (−64%)** |
| 함수 | 36 | 34 | 19 |
| 의도 테스트 74개 | 71/74 | 71/74 | **74/74** |
| 의도 테스트 커버리지 | 53.8% | 56.0% | **98.9%** |
| cat 200MB | 1.77–1.84 s | 1.83–1.91 s | **0.51–0.54 s** |

대조군이 한 일은 **중복 제거형 리팩터링**이었습니다. 모든 옵션을 그대로 두고 반복되는 부분을 새 helper(`usage`, `next_option`, `read_entry`, `close_dir`, 플래그 enum)로 묶었습니다. 파일별로 보면 `common.c`는 오히려 늘었습니다(177 → 181줄, r4는 47줄). 컴파일할 수 없는 환경이었는데도 결과는 테스트 60개를 모두 통과했고, 74개 중 실패한 3개는 r0에서 물려받은 것입니다.

차이는 줄이는 솜씨가 아니라 **기준**에서 났습니다. 비목표 목록이 없으면 AI에게는 모든 기능이 지켜야 할 기능이고, 할 수 있는 일은 같은 기능을 다른 모양으로 다시 쓰는 것뿐입니다. 압축 루프에서 줄어든 542줄 가운데 529줄(r1, r2)은 "이것은 비목표다"라는 판단에서 나왔습니다.

대조군이 74개 테스트에서 더 안전해 보이는 것도 같은 이유입니다. 아무것도 지우지 않았으니 잃을 것도 없었습니다.

## 회의론자

r3와 r0, `INTENT.md`를 Codex에게 읽기 전용으로 주고, 의도를 잃었거나 r0보다 덜 안전해진 곳을 재현 방법과 함께 찾으라고 했습니다(정적 리뷰, [skeptic/codex_last_message.md](skeptic/codex_last_message.md)). 지적은 12건이었습니다. 재현할 수 있는 지적은 모두 먼저 테스트로 만들어 세 버전에 돌렸습니다.

| 분류 | 지적 | r0 | 대조군 | r3 | 처리 |
|---|---|---|---|---|---|
| **압축이 잃은 것** | `cat`, `find`의 쓰기 오류 무시(`/dev/full`, `cat /dev/zero`가 끝나지 않음) | 통과 | 통과 | 실패 | R2가 `ferror(stdout)` 검사를 지움 → 복구 |
| | `find -name a -name b`에서 뒤 조건이 앞 조건을 덮어씀 | 통과 | 통과 | 실패 | R2가 조건을 종류별 변수 하나로 줄임 → argv에서 바로 평가 |

**압축 라운드가 만든 퇴행은 5종이었고, 하나도 원래 테스트 60개에 걸리지 않았습니다.** 넷은 함수 층(R2)에서 "비목표 옵션 파싱"이나 "출력 경로"와 함께 지워졌습니다. 의도에 함축되어 있었지만 테스트로 고정되지 않은 행동들입니다. 하나는 청크 재작성(R3)에서 새로 생겼고 sanitizer만 잡았습니다. 고치는 데 21줄이 들었고 성능은 변하지 않았습니다.

## 무엇을 배웠나

1. **압축의 대부분은 판단에서 나온다.** 줄어든 줄의 97%는 모듈 층과 함수 층(r1, r2)에서 의도 대조로 나왔고 청크 층(r3)은 13줄이었습니다. "반복할수록 압축된다"보다 "첫 두 층에서 판단이 끝나고 그다음은 다듬기"에 가깝습니다.
2. **압축은 오라클의 구멍만큼 의도를 잃는다.** 테스트가 고정하지 않은 행동은 "이건 의도가 아니다"라는 판단에 쉽게 쓸려 나갑니다(쓰기 오류, `--`, 조건 반복). 그래서 회의론자 리뷰는 선택이 아니라 루프의 일부이고, 그 지적은 코드 수정 전에 **테스트와 `INTENT.md` 수정**으로 들어가야 합니다.
3. **커버리지는 지도이지만 완전한 지도는 아니다.** 실행되지 않는 줄은 후보를 잘 보여 줍니다(r0에서 46%, r2 이후 2줄). 하지만 지워진 코드가 하던 일은 커버리지에 보이지 않습니다. 지워진 행동은 회의론자가 이전 버전과 비교해야 보입니다.
4. **줄이면 빨라질 수 있다.** `cat`이 3.5배 빨라진 것은 최적화가 아니라 바이트마다 옵션을 확인하던 분기가 사라졌기 때문입니다(r2 기록).
5. **머리 주석은 비계(scaffolding)였다.** 끝까지 남은 주석은 의도 ID를 적은 것과 *왜*를 설명하는 것뿐이고, 의도 ID 주석은 그대로 추적표가 되었습니다.
6. **대조군과의 차이는 오라클이다.** 같은 모델이라도 비목표 목록 없이 "최소화"를 시키면 리팩터링이 됩니다. 더 안전하지만 거의 줄지 않습니다.

## 한계

- 대상이 812줄, 파일 8개로 작습니다. 대형 프로젝트에서 모듈 층 판단(의존성이 얽힌 경우)이 같은 비율로 작동할지는 검증하지 않았습니다.
- 비목표 목록은 실험 조건으로 제가 정했습니다. 실제 프로젝트에서는 이 목록을 사람이 승인해야 하고, 그 승인이 가장 비싼 단계입니다.
- 라운드를 수행한 것도 AI(Claude)입니다. 같은 절차를 다른 모델이나 사람이 따랐을 때의 재현성은 측정하지 않았습니다.
- 대조군과 회의론자는 각각 한 번만 실행했습니다. r4에는 회의론자 리뷰를 다시 돌리지 않았습니다.
- 테스트 74개 중 14개는 회의론자 리뷰를 보고 추가한 것이라, r4가 74/74인 것은 그 리뷰에 맞춘 결과입니다. 독립된 검증이 아닙니다.
