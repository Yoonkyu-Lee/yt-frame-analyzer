# 두 파일럿에서 배운 것과 모델에 반영할 것

근거는 두 파일럿입니다.
- [pilot-05](pilot-05/README.md): Codex가 쓴 파일 유틸 812줄. 합성 과제.
- [pilot-vnovel](pilot-vnovel/README.md): 실제 바이브 코딩 앱(VNovel Library)의 다운로드 모듈 556줄. 실사용 확인 뒤 main에 병합.

## 배운 것

### 1. 슬롭에는 종류가 있고, 종류마다 맞는 도구가 다르다

| 종류 | 사례 | 무엇이 통했나 |
|---|---|---|
| **기능 슬롭**: 아무도 원하지 않은 기능 | pilot-05 (`find` 식 언어, `touch -t` 날짜 파서) | 비목표 목록을 기준으로 한 압축. 줄어든 양의 97%가 여기서 나옴. 의도 없이 "최소화하라"만 받은 대조군은 7% |
| **장황함 슬롭**: 같은 일을 길게 함 | pilot-vnovel (sidecar 3개, 문자열 sentinel, 인자 9개짜리 함수) | 어떤 방법이든 비슷함. 대조군도 33%를 줄임 |
| **표현 슬롭**: 잘못된 자료 표현·알고리즘 | pilot-vnovel (16구간 고정 분배 → 느린 연결 하나가 끝을 붙잡음) | **재설계만** 고침(6.1초 → 2.3초). 압축과 대조군은 그대로 |

어떤 종류인지는 시작 전에 측정으로 가를 수 있습니다. 의도 테스트가 실행하지 않는 코드가 많으면(pilot-05 원본은 46%) 기능 슬롭입니다. 의도에서 뽑은 벤치마크 시나리오(일부 연결만 느린 경우)가 나쁘게 나오면 표현 슬롭입니다.

### 2. 압축은 지우기만 한다

압축 루프는 자료 표현을 바꾸지 못합니다. 그래서 핵심(자료 표현과 스케줄링)은 의도에서 다시 설계하고 주변부는 압축하는 **혼합(W3)**이 이겼습니다. 의도만 보고 처음부터 쓴 W2는 빨라졌지만 덜 빨라졌고, 압축만 한 W1은 원본 속도 그대로였습니다.

### 3. 가장 비싼 것은 오라클이고, 오라클에도 버그가 있다

pilot-vnovel에서 오라클을 여섯 번 고쳤습니다([ORACLE_CHANGES.md](pilot-vnovel/ORACLE_CHANGES.md)).
- 테스트 서버의 인공물: 연결 수를 잘못 셈.
- 질문 자체의 오류.
- **의도보다 엄격한 테스트**: W2를 부당하게 떨어뜨림.
- 보지 못하는 사각지대: keep-alive, 따로 늦게 오는 꼬리 바이트, 침묵하는 서버.

변경을 모두 기록했고, 바꿀 때마다 모든 버전에 다시 돌렸기 때문에 비교가 정직하게 유지됐습니다.

### 4. 테스트 통과는 의도를 지켰다는 증거가 아니다

회의론자 라운드는 매번 테스트가 보지 못한 회귀를 찾았습니다.
- pilot-05: 원래 테스트 60개를 통과한 결과에서 회귀 5종.
- pilot-vnovel: 숨겨진 테스트를 모두 통과한 재작성 세 개에서 각각 7~8건. 고칠 때마다 다시 리뷰하자 7 → 2 → 2 → 1건으로 줄었습니다.

**고치는 것 자체가 새 회귀를 만듭니다.** 그래서 건수가 0이 될 때까지가 아니라, 심각도가 내려가고 남은 것을 테스트로 막을 때까지 반복했습니다.

### 5. 지적을 말로 기각하면 틀린다

1차 리뷰의 "요청보다 긴 본문" 지적을 저는 "틀린 바이트는 안 들어간다"는 추론으로 넘겼습니다. 2차 리뷰가 반례와 함께 같은 지적을 다시 가져왔습니다. 기각은 그것이 불가능함을 보여 주는 테스트로 하거나, 소유자 결정으로 올려야 합니다.

### 6. 재현 테스트도 먼저 실패해야 한다

처음 만든 재현 테스트는 **고치기 전부터 통과**했습니다. 테스트 서버가 초과 바이트를 정상 바이트와 같은 조각에 실어 보내서 회귀를 재현하지 못한 것입니다. 그 뒤로는 두 가지를 같이 확인했습니다.
- 테스트가 고치기 전에 실패하는지
- 고친 자리를 되돌리면 테스트가 다시 실패하는지(돌연변이 검사)

pilot-vnovel의 수정 13곳이 모두 이 검사를 통과했습니다.

### 7. 리메이크는 감사이기도 하다

원본(실사용으로 검증된 코드)에서 결함을 여럿 찾았습니다.
- 리다이렉트할 때 지정한 Referer가 덮어써짐
- 잘린 파일이 완성되는 두 경로
- 빈 본문에서 취소를 놓침
- 멈춘 서버 앞에서 무한 대기하며 취소도 듣지 않음
- 단일 스트림의 크기 모순을 무시함

**의도를 가진 쪽만** 이것들을 찾았습니다. 대조군과 제 첫 오라클은 놓쳤습니다.

### 8. 최소는 줄이 계속 줄어든다는 뜻이 아니다

556 → 371(W3) → 452(병합본). 회의론자 라운드에서 늘어난 81줄은 모두 의도 D5~D7(서버 오동작, 정체, 취소)을 가리킵니다. "코드는 의도, 측정된 필요, 신뢰 경계로만 늘어난다"는 법칙이 실제로 작동했습니다. 오히려 W3의 371줄은 **너무 작았던** 셈입니다.

### 9. 의도 문서는 라운드를 거치며 자란다

회의론자가 찾은 것 중 일부는 결함이 아니라 **INTENT의 공백**이었습니다. 멈춘 서버를 몇 초 기다릴지, 무엇을 재시도할지, fsync를 할지 같은 것입니다. 이것들은 소유자 결정 목록이 되었고, 소유자가 승인한 뒤 INTENT Revision 1로 들어갔습니다. 소유자 승인 단계는 형식이 아니라 실제로 필요했습니다.

### 10. 정적 투명성: 측정기는 천장에 닿았고, 머리말은 쓸모 있었다

모듈 하나 규모에서는 AI 독자가 원본까지 거의 만점을 받았습니다. 대신 정직한 머리말(`Intent/Data/Assumes/Weak/Cost`)의 `Weak:` 줄이 원본에 숨어 있던 약점("같은 크기의 다른 파일이면 섞인다")을 드러냈고, 실행 결과와도 맞았습니다. 동적 설계(넘겨받기)는 빠르지만 요청 수를 읽기만으로 예측할 수 없게 만듭니다. 성능과 예측 가능성은 실제로 맞바꾸는 관계입니다.

### 11. 실사용에서만 드러나는 것이 있다

다음은 실사용에서만 확인됐습니다.
- 실제 CDN이 엄격해진 검사를 통과하는지
- 9.4GB를 이어받은 뒤 파일이 온전한지(CRC 검사)

그리고 **앱 자체의 관측성 공백**도 드러났습니다. 다운로드 중 메인 창이 사라졌을 때, 창 이벤트를 기록하지 않아서 원인을 가를 수 없었습니다. 진단 로그는 스모크 테스트 **전에** 있어야 합니다.

## 외부 출처에서 들여온 것 (가설, 2026-11-17)

두 파일럿 다음에 본 [poteto 발표](../sources/ai-engineer/all-code-is-slop_O_zcc6Xl12g/)("All Code Is Slop (Except Mine)")가 우리 워크플로의 빈 곳 다섯 가지를 보여 줬습니다. 우리 파일럿으로 확인한 것이 아니므로 모두 *(가설)*로 넣었습니다.

| 빈 곳 | 넣은 것 | 어디 | 근거 |
|---|---|---|---|
| 리캐스트는 누가 마음먹어야 시작되는 행사였다 | 상시 회의 루프: 변경마다(gate), 릴리스마다(근본 회의), 주기마다(의심 하나 이상 닫기) | WORKFLOW 8단계 | 발표: 릴리스마다 퍼징 → 수정 PR |
| 회의론자가 "의도를 지켰나"만 묻고 "더 나은 방법이 있나"는 묻지 않았다 | 네 종류의 의심(전제, 대안, 땜질, 비용)과 기준 방법 대결 | WORKFLOW 3·8단계, NORTHSTAR C12·L14, AGENTS 21·22 | Hayyoth A1(진짜 도구와 나란히), 이 문서 5 |
| 장황함·비효율 의심을 감으로 했다 | 의도 벤치마크와 크기를 CI에서 기준선과 비교, 대결은 숫자로 | WORKFLOW 8단계 리듬 | 발표: 5월 대비 성능표 |
| 교훈이 글(AGENTS.md, INTENT, `Weak:`)로만 남았다 | 래칫: 결함 종류마다 기계 검사. 변명 주석 금지와 gate 경고 | NORTHSTAR C11·L13, AGENTS 19·20, gate ratchet·excuse | 발표: 타이머 1 → 183, 주석 65,824 → 1,227, 린트 7 → 167 |
| 코드를 안 읽는 소유자가 판단할 재료가 없었다 | INTENT `Proof` 열, `Evidence:`는 실제로 돌린 결과 | NORTHSTAR L16, AGENTS 23, templates/INTENT | 발표: 리뷰 = 검증 산출물(영상, 스크린샷, 상태도) |

확인한 것과 못 한 것
- gate의 새 검사 세 가지는 임시 저장소에서 의도대로 PASS/WARN이 갈리는 것을 확인했습니다.
- 변명 주석 검출기는 이 리포의 사람·AI 코드 111개 파일(16,730줄)에서 처음에 2건을 잡았는데, 둘 다 오탐이었습니다(기능 설명의 "later", 변수 이름 `todo`). 낱말을 고른 뒤 0건입니다. **진짜 변명 주석을 잡은 실제 사례는 아직 없습니다.** 이 리포의 코드는 모두 한 번에 쓴 것이라 땜질이 쌓일 시간이 없었습니다.
- 효과(재발이 막히는가, 대결이 더 나은 대안을 찾는가)는 오래 고친 실제 프로젝트에 루프를 몇 주 돌려 봐야 압니다. 그 전까지 이 항목들은 FAIL이 아니라 WARN입니다.
