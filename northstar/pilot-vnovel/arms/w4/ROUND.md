# W4 = W3 + 회의론자 라운드

W3에 대한 Codex 회의론자 지적 16건([skeptic-w3](../../skeptic-w3/codex_last_message.md))을 이렇게 처리했습니다.

1. 구현과 무관하게 재현할 수 있는 지적은 **숨겨진 테스트로** 만들었습니다(오라클 변경 #5, 23 → 26개).
2. 형식에 묶인 지적은 **자체 테스트로** 만들었습니다.
3. 그다음에 고쳤습니다.
4. 고친 자리를 되돌려 테스트가 실패하는지 확인했습니다(돌연변이 검사).

## 2차 회의론자 ([skeptic-w4](../../skeptic-w4/codex_last_message.md))

지적 8건 중 W4가 새로 만든 회귀는 2건이었습니다.

| 지적 | 처리 |
|---|---|
| 구간을 다 채우면 남은 본문을 읽지 않아, 범위를 지키지 않는 서버가 앞쪽에 끼운 엉뚱한 바이트가 파일에 들어감 (1차에서 잘못 넘긴 #7) | 먼저 테스트를 강화했지만, 강화한 테스트가 고치기 전부터 통과해서 재현이 안 됐음. 원인은 테스트 서버가 초과 바이트를 같은 조각에 실어 보낸 것이라, **초과 바이트를 30ms 늦게 따로** 보내게 바꾼 뒤 재현. Content-Length가 구간 길이와 다르면 받기 전에 거부 |
| 잠금 안에서 동기 파일 쓰기 → 디스크가 오래 멈추면 실행기가 굶음 | 머리말의 가정("파일 쓰기는 짧다")에 해당하는 설계상 교환. **기록만** |
| 물려받은 6건 (fsync, 멈춘 서버, 프로브·단일 재시도, 크기를 모르는 단일 스트림의 마지막 total, 정리 실패 무시, 200의 Content-Length 우선순위) | 1차와 같이 소유자 결정 또는 낮음 |

교훈: 1차에서 제가 "문제없다"고 판단한 지적이 2차에서 반례와 함께 돌아왔습니다. 재현 테스트도 처음 만든 것은 회귀를 재현하지 못했습니다. 테스트가 통과한다는 것은 "그 테스트가 본 상황에서는 괜찮다"는 뜻일 뿐입니다.
