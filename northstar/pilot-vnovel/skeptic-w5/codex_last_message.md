Checked and found correct:

- **`wait()` preserves the in-flight future across one-second timeouts.** Passing `&mut fut` does not drop or restart the underlying request each second. Cancellation or final stall exhaustion drops it; the failed stream then drops its response.
- **Retries are bounded:** four attempts, with 0.5/1/1.5-second backoffs. A persistently silent probe or piece phase takes approximately **123 seconds**. This is not a universal whole-download deadline: successful headers/data and separate probe/download phases can extend elapsed time.
- Probe transport failures are retried. HTTP error responses return `Err`, consistent with D2.
- Eight workers issue at most eight concurrent worker requests; the probe response is dropped before workers start.
- Work stealing, accepted-byte accounting, and checkpoints share one mutex. Independently opened worker files have independent cursors; stolen tails are excluded from the donor’s writes.
- Workers are aborted **and awaited** before the final checkpoint or rename.
- Resume loading validates the checksum, marker, total, part length, interval bounds, and overlap. Ordinary torn state is rejected. Fresh segmented initialization removes old state before truncating data.
- Tens-of-GB offsets remain `u64`; slice conversions are bounded by chunk length. No 4 GiB/`usize` truncation was found within the stated scale.
- Segmented progress callbacks are serialized and monotone. Known-length successful paths finish at the total.
- Public signatures, existing derives, and lowercase mode serialization are preserved.
- Explicit request headers, Chrome user agent, redirect limit, connect timeout, and Korean error prefixes are present, subject to the cookie redirect finding.
- An open standard Rust file handle is **not inherently a Windows rename bug**: its default sharing permits deletion/rename.
